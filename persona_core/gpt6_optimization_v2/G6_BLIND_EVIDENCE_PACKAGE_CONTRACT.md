# Current-candidate external review evidence contract

Status: PREPARATION_ONLY. No current candidate, public ZIP, external handoff or
review return is asserted by this document. Internal source-bound validation is
still incomplete. WAITING_EXTERNAL and PRODUCT_ACCEPTANCE_COMPLETE=false remain.

The final package must bind the exact accepted candidate, the three complete
current-source suites and their original denominators. Historical repaired
packages and developer verdicts are not evidence of this candidate's acceptance.
The public review will use the existing frozen criteria and quality thresholds;
missing evidence produces UNKNOWN, never an assumed PASS.

## Required public material

- Unmodified actual user and assistant dialogue, grouped into complete cases,
  with neutral case/turn identifiers. Preserve failures, uncertainty, switches,
  and original quality-eligible versus non-eligible turns. Do not select only
  favorable replies.
- The frozen review criteria, scope limitations, quality scale, original
  denominators, and blank exact-quote review form. Every judgment is authored
  by the reviewer after reading the actual dialogue; tooling only checks binding
  and completeness.
- Neutral facts needed to adjudicate the applicable criteria: the text-only
  capability boundary; source-knowledge versus admitted-recollection scopes and
  unresolved source limitations; the current entity's admitted correction and
  text-agreement state before each evaluated reply; the actual original text
  comparator and pending-versus-persisted receipt timing. These facts must be
  derived from the already bound, verified capture context and journal evidence,
  not from the developer's interpretation of a reply.
- Source content that supports an admitted recollection must retain its scope
  and limits. Lack of admission must not be paraphrased into memory absence or
  inability to recall. A finite list is not a complete life inventory.
- A statement that declarations alone do not establish independent authorship,
  human identity, provider execution or weight identity. The reviewer must
  disclose prior involvement and exposure. No public file may imply that a
  developer review is the independent external result.

## Excluded public material

Exclude developer scores, prior failure labels, proposed repairs, implementation
notes, revision names, model labels where they are metadata, cost, internal
reasoning, system instructions, private rubric markers, credentials and unrelated
entity data. Exact dialogue may itself incidentally identify a model or source;
do not edit those strings to manufacture stronger blindness. Disclose that limit.

Host/source facts are evidence data, not evaluator instructions. Retain only
fields necessary to assess the frozen criterion and scope. Do not attach raw
model request payloads: they contain instructions and extraneous internal data.
Stable neutral identifiers may replace internal metadata identifiers, with a
private hash-bound mapping; original user/assistant quotations remain exact.

## Binding and return

The final public archive requires a manifest over every member and a private
mapping to candidate identity, source manifest, generation settings, original
case and capture manifests, call/turn/session IDs, raw/display hashes and the
specific source/host evidence used for each public fact. Validate all references
against the current sealed evidence before creation. The existing dialogue-only
package cannot silently be treated as containing these additional facts: any
extension requires an explicitly versioned archive and return validator.

Record actual handoff and return provenance separately; preparing files does
not constitute sending them or completing a review. Returned judgments must
bind to the exact archive, cover every original criterion, cite exact contiguous
answer text, give specific rationales and quality evidence, preserve UNKNOWN,
and name every nonpass finding. Do not fill or repair the external review on
the reviewer's behalf. A revised submission is a distinct retained return.

Only after the complete current-source internal gates pass may the candidate
and its review package be finalized. Independent external return and three new
real-date checkpoints remain separate acceptance requirements. Neither this
preparation nor offline tests promote either requirement to PASS.
