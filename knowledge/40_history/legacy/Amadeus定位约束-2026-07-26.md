# Amadeus 定位约束（2026-07-26 会话确认）

来源：用户在 2026-07-26 会话中的直接答复（非推测）。后续会话做架构决策时以本文为准，除非用户更新。

1. **定位**：尚未定型，当前为预研阶段。→ 架构须对「拟人陪伴 / 助理+陪伴混合 / 多租户产品」三种定位保持中立；拟人化特性（人格注入、错别字、打字节奏）做成可整体关停的策略层，不下沉进核心。
2. **部署与规模**：小规模自托管（本人 + 少量群/好友）。→ 单实例进程组 + 嵌入式存储（SQLite WAL + 本地向量文件）；不引入外部 DB/MQ；记忆门面、接入网关、模型编排三处接口按 RPC 形状设计，预留服务化切割线。
3. **许可证**：纯开源，GPL 可接受。→ 对 GPL-3.0 参照物（MaiBot / A_Memorix）的清洁室约束解除，可直接复用代码；但复用即锁定 GPL 兼容族、丧失闭源选项，须显式立 ADR-005 决策，不得默认发生。
4. **平台优先级**：Telegram/Discord + QQ + 自有前端（网页/App）三线并行。→ 平台无关消息内核为强制需求（P0）；适配器单轨制（适配器=受管扩展）；接入域须暴露一等 API/WS 契约支撑自有前端；消息 schema 以三平台能力交集为核心组件、扩展组件承载平台特性。

**建议 ADR 顺序**（在定位未定的前提下仍同构可先行）：ADR-002 决策循环形态（单 Agent 工具循环）→ ADR-003 记忆引擎边界（门面+可置换内核）→ ADR-004 扩展战略（MCP-first，插件运行时后置）→ ADR-005 GPL 代码复用决策。ADR-001（定位与租户模型）待定型后补。
