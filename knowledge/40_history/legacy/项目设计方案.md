# Amadeus Soul 项目设计方案

> 版本 v1.0 · 2026\-07\-27 · 基准：本地代码快照（plugin.py 2026\-07\-26 23:49，含 CMD\_PATCH\_V2）
> 
> 标签约定：未单独标注的技术陈述均直接来自源码/日志阅读（\[KNOWN\]）；推断与未知逐条标注 \[INFERRED\]/\[UNKNOWN\] 并给置信度。

## 一、定位与边界（先划清不做什么）

**一句话**：Amadeus Soul 是 MaiBot（麦麦）1.x 的插件，为 QQ 私聊注入 Amadeus 红莉栖式"自主意识"——她主动开口，而不是等消息。

| 在边界内 | 明确不做（归宿主或留给未来） |
| --- | --- |
| 单一私聊对象的主动消息 | 群聊、多目标并行 |
| 七类主动场景 \+ 防打扰闸门 | 被动回复逻辑（完全归 MaiBot 主程序） |
| 本地事实/约定/纪念日记忆 | 云端记忆、向量检索 |
| 借宿主的 LLM 与消息通道 | 自建模型接入、跨平台适配 |

**与「Amadeus 架构」大项目的关系** \[INFERRED, MED\]：当前插件是 Amadeus 的第一个落地形态——借 MaiBot 当宿主换取最短路径。项目库《naga\-架构评审》的七条决策（原生 function calling、单一核心对象、真流式、配置零硬编码等）是未来脱离宿主、独立成系统时的设计约束；在插件形态下不适用，因为契约由宿主 SDK 支配。

## 二、总体架构与数据流

```text
              （被动旁路：她在"听"）
用户消息 ─ON_MESSAGE→ observe_message ─→ 滚动上下文(≤40) / 待提取队列(≤30) / 首次自动绑定
宿主发言 ─AFTER_SEND→ observe_send   ─→ 滚动上下文

              （主动主链：她在"活"）
心跳 asyncio 任务（每 tick_seconds=300s；/amadeus poke 可即时唤醒）
 └→ _tick
     1. 记忆整理（静默时段也运行）：待提取队列 ─LLM→ 事实/约定/纪念日 → memory.json
     2. 闸门链：总开关/暂停 → 目标定位 → 静默时段 → 每日额度 + 冷却
        （被无视 ≥2 条：阈值 +2、额度减半——"退避"）
     3. 刺激源收集（7 类）：早安窗口 / 晚安窗口 / 久未联系 / 纪念日 /
        约定到期回访 / 对话余韵 / 随机灵感
     4. 自主思考：人设+时刻+心情+记忆摘要+近期对话+最近主动消息+刺激
        ─LLM→ {impulse: 0-10, scene, message, reason}
     5. 表达判定：impulse ≥ threshold 且与最近 5 条主动消息不雷同
        （字符集 Jaccard > 0.75 视为重复）
     6. ctx.send.text 发送 → 更新额度/冷却/场景标记/上下文 → state.json 落盘
```

核心架构决策：**思考权在 LLM（说不说、说什么），约束权在代码（何时允许说、每天几次）**。LLM 失控最多浪费一次思考，不会骚扰用户——这是整个插件最重要的分权设计。

## 三、核心模块

| 模块 | 职责 | 关键实现 |
| --- | --- | --- |
| 配置层（8 个 Section） | config.toml ↔ WebUI 设置页 | 声明式 schema；`plugin.config_version` 为宿主硬性要求 |
| 事件观察 | 维持时间感与上下文 | 纯观察不拦截（weight\=0）；配置 user\_id 后收到其私聊即自动绑定 |
| 心跳循环 | 她的"时间" | 常驻 asyncio 任务；异常不退出；poke 事件即时唤醒 |
| 目标定位 `_ensure_stream` | 找到"该找谁" | 优先级：手填 stream\_id → 已绑定 → user\_id 查询 → 唯一私聊流；失败每小时仅提醒一次 |
| 硬闸门 | 防打扰 | 静默时段（支持跨午夜）、每日额度、冷却分钟、被无视退避 |
| 刺激源 | 她"注意到"的事 | 七类，各带场景名与提示语；场景完成打日戳防同日重复 |
| 思考引擎 `_think` | 决定开口与内容 | 单次 LLM 调用 ≤400 token；JSON 三层鲁棒抽取（剥围栏→首尾大括号→深度扫描） |
| 记忆子系统 | 长期记住对方 | 三类 fact/promise/date；精确串去重；超 120 条按（重要度, 新鲜度）淘汰；约定回访后标记 done |
| 命令控制台 | `/amadeus` 七个子命令 | bind / status / pause / resume / poke / memory / forget；解析双路兜底（CMD\_PATCH\_V2） |

## 四、接口契约

### 4\.1 对宿主 SDK（maibot\-plugin\-sdk）的依赖面

| API | 用途 | 防御策略 |
| --- | --- | --- |
| `ctx.send.text(text, stream_id)` | 发送消息 | — |
| `ctx.llm.generate(prompt, model, temperature, max_tokens)` | 思考 / 记忆提取 | 返回 dict/str 双形态兼容；失败放弃本轮、不重试 |
| `ctx.chat.get_stream_by_user_id` / `get_private_streams` | 定位私聊 | stream 描述多键名防御解析（stream\_id/id/streamId/chat\_id/嵌套） |
| `EventType.ON_MESSAGE` / `AFTER_SEND` | 观察 | EventType 导入位置双路兜底（types 子模块 ↔ 顶层） |
| `Command(pattern=...)` | 命令入口 | 宿主 match 对象缺失时回退到消息原文正则抠子命令 |
| manifest `capabilities` 5 项 | 声明权限 | 宿主校验口径不一时按报错增删（README 已写明） |

### 4\.2 数据契约（`plugins/amadeus_soul/data/`）

- `state.json`：绑定流、日额度计数、冷却/静默/余韵时间戳、未回复计数、暂停位、滚动上下文（≤40 条、每条截断 300 字）、最近主动消息（≤8）、场景标记（≤200）、待提取队列（≤30）。**所有集合均设上界——状态文件不会无限膨胀。**
- `memory.json`：`[{kind: fact|promise|date, content, importance, ts, due?, done?, date?}]`，≤120 条。
- 删除 `data/` 目录 \= 完全重置。

### 4\.3 LLM 契约

- 思考输出：`{"impulse": 0-10, "scene": str, "message": str, "reason": str}`；
- 记忆提取输出：`{"facts": [...], "promises": [...], "dates": [...]}`；
- 两处均为"只输出 JSON"指令 \+ 三层鲁棒解析兜底。

## 六、部署拓扑

```text
Windows 开发机（D:\amadues bot）             云服务器 HOST（公网仅 PORT 端口探通）
┌────────────────────────────┐  scp+ssh   ┌──────────────────────────────────────┐
│ amadeus_soul/   源码        │ ─────────→ │ /tmp/zip+sh → unzip →                │
│ amadeus_soul_plugin.zip     │            │ /opt/MaiBot/src/plugins/amadeus_soul │

└────────────────────────────┘            │ QQ ⇄ NapCat ⇄ MaiBot ⇄ 本插件        │
                                          └──────────────────────────────────────┘
```

- 发布流程：改代码 → 重打 zip → 双击「一键安装到服务器.bat」（输两次密码）→ 自动定位、解压、重启容器。
- 容器名含 napcat → QQ 协议端为 NapCat，与 MaiBot 同容器/同 compose 部署 \[INFERRED, MED\-HIGH\]。
- `unzip -o` 只覆盖 zip 内文件 → 线上 `data/`（状态\+记忆）在升级中天然保留。
- WebUI 公网可达性未验证；仅 PORT 端口确认开放，访问 WebUI 可走 SSH 隧道：`ssh -L LOCAL_PORT:TARGET_HOST:TARGET_PORT -p SSH_PORT ACCOUNT@HOST` \[INFERRED\]。

## 八、演进路线

- **P0（本周，让她真正活起来）**：重跑一键安装 → WebUI 确认插件启用 → 填 `user_id` 或 bind → `/amadeus poke` 全链路验证 → 观察 24h 主动行为与日志。
- **P1（稳定性）**：修 \#4/\#5；结构化日志（每次思考落一行 JSON：scene/impulse/是否开口）；`/amadeus status` 增加"最近 3 次思考"回显，免上服务器看日志。
- **P2（体验）**：记忆语义去重与时间衰减；约定的相对日期解析（"下周五"）；主动消息类型扩展（图片/语音，取决于宿主 capabilities）；多目标支持（每目标独立状态机）。
- **P3（脱离宿主，并入 Amadeus 主架构）**：按《naga\-架构评审》七条决策重构为独立服务——原生 function calling、单一核心对象、真流式、manifest 与运行时对齐、密钥零硬编码；届时本插件降级为其 QQ 通道适配器。

## 九、部署后验收清单

1. WebUI 插件页可见 Amadeus Soul 且已启用；
2. 私聊 `/amadeus status` 返回状态卡，绑定流不是"未绑定"；
3. `/amadeus poke` 后 60 秒内收到主动消息；
4. `data/state.json`、`memory.json` 已生成且随对话增长；
5. 次日 08:00–09:30 收到早安（当日仅一次）；
6. 聊天中提"明天要交报告"，20 分钟后 `/amadeus memory` 能看到该约定；
7. 连续两条主动消息不回复后，她的频率明显下降（退避生效）。
