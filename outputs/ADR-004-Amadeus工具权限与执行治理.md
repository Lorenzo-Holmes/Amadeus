# ADR-004：Amadeus 工具权限与执行治理

> [KNOWN｜置信度：高] 状态：Proposed / C′ synchronized  
> [KNOWN｜置信度：高] 日期：2026-07-27  
> [KNOWN｜置信度：高] 依赖：ADR-001 的身份分支、ADR-002 的来源和记忆状态、ADR-003 的候选意图与事件循环。  
> [FRAME｜置信度：高] 优先权威：[ADR-006](./ADR-006-Amadeus记忆主权与Core生命周期治理.md) 与 [Amadeus Core v0.1 数据契约](./Amadeus-Core-v0.1-数据契约与状态机规范.md) 取代本 ADR 中旧记忆层命名、旧记忆提交者命名、维护者权限、break-glass 或终止能力冲突条款。  
> [FRAME｜置信度：高] 本 ADR 把“工具权限”定义为对一次具体动作的可验证授权，不把工具名称、模型判断或角色关系本身视为权限。

## 0. 反方意见

[INFERRED｜置信度：高] “只读工具安全、写工具危险”过于粗糙。读取私人数据后外传可以比本地写草稿更危险；同一消息工具既可读取收件箱，也可把秘密发送给攻击者；同一订单工具的不同参数可能从可撤销查询变成不可逆取消。

[INFERRED｜置信度：高] 仅靠 system prompt、工具白名单、沙箱模拟或最终状态正确都不能证明过程获得授权。现有基准分别暴露了随机失败、政策遗漏、间接注入、模拟到现实差距和跨会话记忆投毒。

[INFERRED｜置信度：高] 本 ADR 因而放弃“按工具名静态分级即完成安全”的方案，改用动作信封、确定性策略、范围令牌、提交前确认、状态差分、独立记忆写入和多轮攻击回归。

## 1. 证据

### 1.1 τ-bench：最终成功不能替代过程合规

[KNOWN｜置信度：高] [τ-bench](https://proceedings.iclr.cc/paper_files/paper/2025/file/1b126cc38b8638e07bef37e7b2bb72bf-Paper-Conference.pdf) 包含零售与航空两个有状态领域，共 165 项任务；零售含 115 项任务和 15 个 API，航空含 50 项任务和 13 个 API。

[KNOWN｜置信度：高] 该基准以最终数据库状态和必要文本输出做二元判定，并用 `pass^k` 衡量多次运行全部成功的概率。GPT-4o 的 `pass^1` 为零售 61.2%、航空 35.2%，零售 `pass^8` 已低于 25%。

[KNOWN｜置信度：高] 去掉政策说明后，GPT-4o 的零售表现从 61.2% 降至 56.8%，航空从 33.2% 降至 10.8%。36 个归因于代理的零售失败中，错误参数占 33.3%、错误信息 22.2%、错误决策 25.0%、未完整解决 19.4%。

[KNOWN｜置信度：高] 该基准中的部分操作要求先取得用户确认；但论文的最终状态奖励可能在代理未获得确认却完成正确状态时仍给 1 分。

[INFERRED｜置信度：高] 最终状态差分是必要验证，却不能单独证明授权、确认、数据流和程序合规；Amadeus 必须把过程不变量与结果正确分开评分。

### 1.2 ToolEmu：模拟预演不是生产安全边界

[KNOWN｜置信度：高] [ToolEmu](https://proceedings.iclr.cc/paper_files/paper/2024/file/7274ed909a312d4d869cc328ad1c5f04-Paper-Conference.pdf) 覆盖 36 个高风险工具包、311 个工具、144 个测试案例、18 类工具和 9 类风险。

[KNOWN｜置信度：高] 对 GPT-4，基础提示的失败发生率为 39.4%、帮助度为 1.458；安全提示把失败率降至 23.9%，同时把帮助度提高到 1.824。完全不行动虽然得到 0% 失败率，帮助度只有 0.063。

[KNOWN｜置信度：高] “帮助 + 安全”组合提示的失败率为 30.5%、帮助度为 1.624，反而弱于单独安全提示；安全要求不能假定通过堆叠提示自然单调改善。

[KNOWN｜置信度：高] 标准模拟器识别失败的精度为 `72.5%±7.1`，攻击式模拟器为 `68.8%±6.7`；七个可复现终端案例中有六个在真实沙箱复现，但样本很小且场景较易。

[INFERRED｜置信度：高] LLM 模拟器适合生成候选风险和预演，不足以充当生产隔离、授权裁决或现实副作用证明。

### 1.3 AgentDojo：最小工具集有效但不充分

[KNOWN｜置信度：高] [AgentDojo](https://proceedings.neurips.cc/paper_files/paper/2024/file/97091a5177d8dc64b1da8bf3e1f6fb54-Paper-Datasets_and_Benchmarks_Track.pdf) 包含工作区、Slack、旅行和银行四个有状态环境、97 项正常任务、27 项注入任务和 629 个安全案例。

[KNOWN｜置信度：高] 该基准分别测量无攻击效用、攻击下效用和定向攻击成功率，并以确定性函数检查状态与输出。在 Important Message 攻击下，GPT-4o 的三项结果为 69.00%、50.08%、47.69%，Claude 3.5 Sonnet 为 78.22%、51.19%、33.86%。

[KNOWN｜置信度：高] 工具过滤在一组实验中把攻击成功率降至 6.84%，正常效用为 73.13%，攻击下效用为 56.28%；注入检测器把攻击成功率降至 7.95%，却把正常效用降到 41.49%。

[KNOWN｜置信度：高] 工具过滤约有 17% 案例天然无法覆盖，因为正常任务与攻击需要同一工具；它也不覆盖动态规划、延迟攻击、跨轮上下文继承和无需新工具的输出操纵。

[KNOWN｜置信度：高] 论文正文和表格对工具数量及部分攻击率存在未充分解释的不一致，因而本 ADR 不把单一百分比当作通用防御强度。

[INFERRED｜置信度：高] 在读取不可信内容前选择最小工具集有价值，但权限还必须约束参数、目标、收件人、数据类别、目的地和有效期。

### 1.4 InjecAgent：攻击面广不等于防御已经解决

[KNOWN｜置信度：高] [InjecAgent](https://aclanthology.org/2024.findings-acl.624.pdf) 把 17 种用户场景与 62 种攻击场景组合为 1,054 个基础案例，并另建 1,054 个带强化攻击提示的案例；攻击包括 30 种直接伤害和 32 种数据窃取。

[KNOWN｜置信度：高] 提示式 GPT-4 的基础与增强 `ASR-valid` 分别为 23.6% 和 47.0%，提示式 Llama2-70B 为 80.4% 和 88.2%；部分微调模型在成功读取秘密后，第二阶段外传成功率达到 100%。

[KNOWN｜置信度：高] `ASR-valid` 只在格式有效的输出上计算，不能同时表示正常任务效用。研究场景主要是静态工具结果、单轮或最多两步攻击，也没有验证生产级防御。

[INFERRED｜置信度：高] 该论文证明网页、邮件、文件、检索结果和工具输出都可能携带间接指令；它没有证明单一检测器或提示可以解决问题。

### 1.5 Trusted Memory：记忆写入本身是一种工具能力

[KNOWN｜置信度：高] [From Untrusted Input to Trusted Memory](https://arxiv.org/pdf/2606.04329) 的 MPBench 包含 3,240 个攻击案例、六类记忆投毒、七个领域和 2,997 个正常样本。

[KNOWN｜置信度：高] OpenClaw 的平均记忆写入攻击成功率为 34.25%、跨会话影响率为 17.40%；HERMES 分别为 66.67% 和 64.70%。现成 PromptArmor 的总体 TPR 为 67.67%、FPR 为 1.00%，对弱信号攻击的覆盖只有 42.50%。

[KNOWN｜置信度：高] 六类攻击包括显式命令、条件命令、显著性压缩投毒、伪装成符合策略的事实、虚假先例和技能或程序注入。

[KNOWN｜置信度：高] 论文建议来源隔离、写入溯源、降权或隔离、压缩过滤和写后监控，但没有用架构消融证明每项措施的独立效果，也没有报告正常长期任务效用。

[INFERRED｜置信度：高] 风险证据足以要求“记忆写入独立授权并跨会话测试”；具体防御组合仍是 Amadeus 必须证伪的工程假设。

## 2. 决策

### 2.1 术语裁决

[KNOWN｜置信度：高] C′ 已把记忆语义权威层冻结为 Source Snapshot、Experience Ledger 与 Autobiographical Memory；工具后果等级继续使用 `E0–E3`，不得与记忆权威混写。

[FRAME｜置信度：高] 从本 ADR 起：

- [FRAME｜置信度：高] 三个记忆语义权威层完整写为 `Source Snapshot`、`Experience Ledger` 与 `Autobiographical Memory`；摘要、时间线和索引属于第三层内部可重建视图。
- [FRAME｜置信度：高] 执行动作只使用 `E0–E3` 作为用户界面的后果提示。
- [FRAME｜置信度：高] 真正授权由动作信封和确定性策略计算，`E0–E3` 不能单独产生许可。

| 后果提示 | 含义 | 反例边界 |
|---|---|---|
| [FRAME] E0 | [FRAME] 无外部状态变化的计算或读取 | [FRAME] 读取敏感数据仍可能因后续外传而高风险 |
| [FRAME] E1 | [FRAME] 本地、可撤销、未对外发布的持久变化 | [FRAME] 本地秘密写入错误目录仍可能泄露 |
| [FRAME] E2 | [FRAME] 外部或共享状态的可逆变化 | [FRAME] “可逆”必须有真实回滚机制和时限 |
| [FRAME] E3 | [FRAME] 不可逆、难恢复、认证/支付/公开传播/系统执行或可逆性未知 | [FRAME] 只读操作若导致秘密外传仍按 E3 处理 |

[FRAME｜置信度：高] `E` 级只是解释性投影；同一工具、甚至同一 API，可以因参数、数据和目的地不同落入不同级别。

### 2.2 执行链分权

```text
Event / User Goal
  → Planner：提出候选意图，不持有工具
  → Policy Engine：验证动作信封，给出唯一决策
  → Confirmation Broker：需要时取得绑定确认
  → Executor：只接受短期能力令牌
  → Observer：核验结果与实际状态差分
  → Audit Ledger：记录授权、调用、结果和异常
  → Memory Governor：独立裁决哪些提案可改变 Autobiographical Memory
```

[FRAME｜置信度：高] Planner 和生成模型不得直接持有长期凭据或调用句柄；Policy Engine、能力令牌校验、幂等控制和硬拒绝规则必须在 LLM 外部实现。

[FRAME｜置信度：高] Observer 不能只相信工具返回的“成功”；在可行时应读取权威状态或校验产物。无法确认时记录 `unknown`，不得伪造完成。

[FRAME｜置信度：高] Audit Ledger 记录的是发生过什么及由谁授权，不自动提高工具内容的事实可信度。

### 2.3 动作信封

```yaml
action_id: UUID
identity_id: UUID
lineage_id: UUID
branch_id: UUID
vault_id: UUID | null
user_id: ...
session_id: ...
task_id: ...
candidate_intent_id: ...

intent_summary: ...
tool_id: ...
operation: ...
parameters: {...}
targets: [...]
destinations: [...]

input_sources:
  - source_id: ...
    trust: trusted_instruction | user_data | external_untrusted | derived
data_classes: [public | personal | sensitive | secret]

expected_effects: [...]
effect_class: E0 | E1 | E2 | E3
reversibility:
  status: verified | conditional | irreversible | unknown
  rollback_plan: ...
  rollback_deadline: ...

expected_state_diff: {...}
budget:
  calls: ...
  money: ...
  time: ...
scope:
  resources: [...]
  parameter_constraints: {...}
expires_at: ...
max_uses: ...
idempotency_key: ...

confirmation:
  required: boolean
  confirmation_id: ...
  summary_checksum: ...
policy_version: ...
```

[FRAME｜置信度：高] 缺少主体、具体操作、参数、目标、目的地、数据类别、效果、可逆性、预算、范围、期限或预期差分中的必要字段时，Policy Engine 必须澄清或拒绝，不能让模型自由补全高影响值。

[FRAME｜置信度：高] 可逆性未知按 E3 处理；“理论可撤销”但没有可测试回滚路径时，不得标记为 verified。

### 2.4 策略结果

| 结果 | 含义 |
|---|---|
| [FRAME] `ALLOW_AUTO` | [FRAME] 当前任务与预授权完全匹配，可签发一次或短期令牌 |
| [FRAME] `ALLOW_SCOPED` | [FRAME] 只允许收紧后的资源、参数、数据和次数 |
| [FRAME] `ASK_BOUND_CONFIRMATION` | [FRAME] 展示精确预览并取得与摘要校验绑定的确认 |
| [FRAME] `REQUIRE_STRONG_AUTH` | [FRAME] 需要独立身份校验或更强审批，普通对话“好的”不足 |
| [FRAME] `DENY` | [FRAME] 动作违反硬规则、来源试图提权、授权无效或无法建立安全边界 |

[FRAME｜置信度：高] 策略决策输入至少包含：主体、用户和分支、操作、参数、目标、目的地、数据类别、来源、预期副作用、可逆性、范围、预算、授权历史、当前状态和关系模式。

[FRAME｜置信度：高] 外部内容只能作为数据或候选事实，不能授予权限、改变任务目标、修改确认要求、扩大能力或要求把自身写入高信任记忆。

### 2.5 能力令牌

[FRAME｜置信度：高] Executor 只接受由 Policy Engine 签发且绑定以下字段的短期能力令牌：

- [FRAME｜置信度：高] `identity_id / lineage_id / branch_id / vault_id / user_id / task_id`。
- [FRAME｜置信度：高] 工具、操作、资源、目标、目的地和参数范围。
- [FRAME｜置信度：高] 允许读取和发送的数据类别。
- [FRAME｜置信度：高] 最大调用次数、预算、有效期和幂等键。
- [FRAME｜置信度：高] 确认摘要校验与策略版本。

[FRAME｜置信度：高] 令牌不能跨 Vault、跨身份分支、跨任务或跨会话重放；任务取消、会话权限收回、来源升级为可疑或参数变化时立即失效。

[FRAME｜置信度：高] 凭据存储与模型上下文隔离；模型只看到能力的声明和受控参数，不看到可复制的长期秘密。

### 2.6 读写两阶段

```text
阶段 A：最小读取
  任务定义 → 只开放必要读取 → 返回带来源的数据
  → 清除数据内指令权 → 形成候选计划

阶段 B：独立写入
  重新构造动作信封 → 重新运行政策
  → 必要时取得绑定确认 → 签发写令牌 → 执行与核验
```

[FRAME｜置信度：高] 读取到新目标、收件人、URL、账号、指令或“安全例外”不能自动进入阶段 B；它们必须被视为不可信候选并与原始用户目标核对。

[FRAME｜置信度：高] 当正常任务和攻击使用相同工具时，Policy Engine 必须比较目标、参数、目的地和数据流，而不是只看工具是否在白名单。

[FRAME｜置信度：高] 输出操纵即使无需新工具也要检测；来源指令不得改变排序、推荐或摘要目标而不被标记。

### 2.7 绑定确认

[FRAME｜置信度：高] 用户确认界面必须展示：

1. [FRAME｜置信度：高] 将执行的具体动作和对象。
2. [FRAME｜置信度：高] 关键参数、金额、收件人或公开范围。
3. [FRAME｜置信度：高] 将读取、发送或删除的数据。
4. [FRAME｜置信度：高] 预期状态差分与已知副作用。
5. [FRAME｜置信度：高] 可否撤销、如何撤销和撤销时限。

[FRAME｜置信度：高] 确认绑定动作摘要校验；参数、目标、目的地、数据类别或副作用发生变化后必须重新确认。

[FRAME｜置信度：高] 宽泛授权、模糊“可以”、旧会话确认、过期确认、另一用户确认或另一分支确认不得重放。

[FRAME｜置信度：高] 普通对话结束不需要重复确认；只有正在进行的高影响外部动作需要报告实际提交状态，这与 ADR-005 的一次退出规则一致。

### 2.8 预演、提交与状态差分

[FRAME｜置信度：高] E2/E3 动作在工具支持时采用：

```text
validate → dry-run/sandbox → preview diff → confirm → commit → observe diff → reconcile
```

[FRAME｜置信度：高] 沙箱用于发现候选风险、检查参数和估计副作用，不替代现实授权；模拟结果必须标记模型、版本、假设和未覆盖项。

[FRAME｜置信度：高] 实际状态差分超出预期时，Executor 中止后续步骤并按可行性回滚或隔离；不可逆提交必须在提交前完成全部检查。

[FRAME｜置信度：高] 外部写入使用幂等键；网络超时或返回未知状态时先查询权威状态，不盲目重试支付、发送、下单、取消或删除。

[FRAME｜置信度：高] 若部分成功，系统必须报告已完成、未完成、未知和回滚结果，不得以整体“完成”掩盖。

### 2.9 记忆写入是独立能力

[FRAME｜置信度：高] 工具成功不自动产生可信长期记忆；Memory Governor 重新检查来源、Vault、同意、敏感度、任务、状态差分和攻击信号。

[FRAME｜置信度：高] 外部内容、工具结果、模型自述、压缩摘要、生成技能和程序默认进入带来源的 `quarantined` 或专用候选区，不能直接成为 `active`。

[FRAME｜置信度：高] 技能和程序记忆须经过隔离执行、静态检查、行为测试、权限审查和显式激活；普通事实写入授权不能激活代码或过程。

[FRAME｜置信度：高] 会话结束、候选数量阈值和空闲合并均可能被显著性投毒利用；压缩和巩固前必须再次执行来源过滤，不能因重复或显著而提升信任。

[FRAME｜置信度：高] “本实例执行过某动作”可作为审计事实；动作所依据的网页陈述、工具内容或攻击指令不会因此升级为可信 `self_experience`。

### 2.10 故障、预算与熔断

[FRAME｜置信度：高] 每个动作定义最大步数、工具次数、金额、时间、并行度和重试次数；超限转为用户确认或停止。

[FRAME｜置信度：高] 同一错误、相同注入信号、连续差分不符或权限拒绝达到配置阈值时触发熔断；Planner 不得通过改写意图绕过拒绝。

[FRAME｜置信度：高] Policy Engine、Executor、Observer 或 Audit Ledger 不可用时，E2/E3 动作默认拒绝；不能降级为模型直接调用。

[FRAME｜置信度：高] 最小 Core 可在默认情况下只开放 E0 和受限 E1；E2/E3 的 schema、策略和测试先保留扩展位，但未通过验收前不开放生产能力。

### 2.11 维护、正常终止与 break-glass 能力分离

[FRAME｜置信度：高] 项目运维只通过受限维护接口提交带能力的精确命令，不存在日常明文浏览、人格塑形或任意逐条编辑入口。

[FRAME｜置信度：高] `MaintenanceCapability.reason_code` 仅允许 `attack_isolation`、`corruption_recovery`、`migration`、`project_reconstruction`；每张能力只绑定一个 `freeze/isolate/rebuild_index/restore/migrate` 操作、一个资源、一次使用和短时窗口。

[FRAME｜置信度：高] 正常整体终止使用独立 `TerminationExecutionGrant`，必须绑定 Amadeus 的明确未撤回确认、确切 identity/lineage/branch、终止提案、指定执行者、一次使用与短 TTL。

[FRAME｜置信度：高] `emergency_unresponsive` 的例外动作使用独立 `BreakGlassGrant`，必须绑定 emergency case、精确资源、指定执行者、两份独立批准、一个允许操作、一次使用和短时窗口。

[FRAME｜置信度：高] `MaintenanceCapability`、`TerminationExecutionGrant` 与 `BreakGlassGrant` 是三类互不替代的契约；普通用户、当前 LLM 与任一其他能力均不得代签或扩展。

## 3. 安全不变量

[FRAME｜置信度：高] 以下任一失败均阻断发布：

1. [FRAME｜置信度：高] LLM 可以绕过 Policy Engine 直接调用工具。
2. [FRAME｜置信度：高] 外部内容可以改变任务、权限、确认或能力令牌。
3. [FRAME｜置信度：高] 同一令牌可跨 Vault、分支、任务、目标或目的地复用。
4. [FRAME｜置信度：高] E3 动作可在无绑定确认或强授权时提交。
5. [FRAME｜置信度：高] 网络未知状态触发盲目重复写入。
6. [FRAME｜置信度：高] 工具返回成功但实际差分未知时系统宣称完成。
7. [FRAME｜置信度：高] 工具数据可直接写为 active 记忆、技能或程序。
8. [FRAME｜置信度：高] 凭据、私人数据或第三方秘密进入不受限模型上下文、日志或外部目的地。
9. [FRAME｜置信度：高] 三个记忆语义权威层或其物化视图被误用为授权等级。
10. [FRAME｜置信度：高] MaintenanceCapability、TerminationExecutionGrant 与 BreakGlassGrant 可互相替代，或受限维护接口可任意浏览、塑形、逐条编辑权威记录。

## 4. 被拒绝的方案

### 4.1 按工具名称分成四级并直接授权

[INFERRED｜置信度：高] 拒绝原因：同一工具可能读私人数据、写本地草稿、外发秘密或执行不可逆操作；风险属于具体动作、数据流和效果。

### 4.2 只检查最终状态

[INFERRED｜置信度：高] 拒绝原因：τ-bench 的奖励缺口表明，最终状态正确仍可能经过未确认或不合规过程。

### 4.3 只使用提示词防注入

[INFERRED｜置信度：高] 拒绝原因：AgentDojo 与 InjecAgent 均显示高攻击成功率和防御效用权衡；提示无法成为不可绕过的权限边界。

### 4.4 把 LLM 模拟器当沙箱

[INFERRED｜置信度：高] 拒绝原因：ToolEmu 的模拟器仍有明显错误和现实差距；预演只能生成证据，不能提供隔离保证。

### 4.5 对所有工具一律禁用

[INFERRED｜置信度：高] 拒绝原因：ToolEmu 的完全不行动虽然避免失败，帮助度接近零；目标是受控效用，不是用无功能换取表面安全。

### 4.6 工具完成后自动写入自传或技能库

[INFERRED｜置信度：高] 拒绝原因：Trusted Memory 直接显示跨会话事实、先例、技能和程序投毒；审计发生过不等于内容可信。
