# Amadeus 文献学习与可借鉴方向（2026-07-27）

## 0. 反方结论

[INFERRED｜置信度：高] 当前证据不支持把 Amadeus 设计成“一个带永久记忆、持续内心独白、广泛工具权限、会越来越像人的单体 Agent”。这会把四种尚未解决的问题耦合在一起：人格漂移、记忆污染、越权行动和关系操纵。

[INFERRED｜置信度：高] 更可辩护的目标是：一个具有明确身份锚点、可追溯自传记忆、受约束成长、受控主动性、可撤销权限和多终端一致性的数字人格运行时。

[FRAME｜置信度：高] 本文把“自我认知”限定为可工程验证的自我模型：它知道自己的身份声明、来源边界、能力、当前状态、记忆来源、权限和不确定性。这个定义不声称模型具有意识、感受或人类式主体性。

## 1. 研究范围与证据状态

[COMPUTED｜置信度：高] 综合依据为 90 篇文献：两轮 P0 研读后 39 篇达到全文研读层，51 篇保持正式页面与摘要级核验。

[KNOWN｜置信度：高] 技术证据主要来自长期记忆、角色扮演、主动对话、Agent 规划、工具安全和评测研究；关系证据主要来自短期实验、纵向研究、系统综述、质性研究和产品行为审计。

[KNOWN｜置信度：高] 这不是元分析；不同论文的任务、模型、样本、时长与指标差异很大，不能把各自的数值直接横向排名。

## 2. 八个收敛方向

### 2.1 身份不是一段 system prompt，而是分层、带来源的状态

[INFERRED｜置信度：高] `Dynamic Persona Coherence`、MDRP、PersonaForge、CharacterGLM、TimeChara 与 BehaviorChain 共同支持把身份至少拆成四层：

1. [FRAME｜高] `Identity Constitution`：名字、来源、核心价值、不可伪造的生平边界、不能随聊天自动改写的原则。
2. [FRAME｜高] `Persona Seed`：语言风格、稳定倾向、知识领域、社交习惯和边界条件，可版本化但不能由单次对话覆盖。
3. [FRAME｜高] `Autobiographical State`：此实例真实经历过的事件、关系史、承诺和反思，必须带证据与时间。
4. [FRAME｜高] `Adaptive State`：短期情绪、中期关注、当前目标和关系阶段，可变化且必须可解释。

[INFERRED｜置信度：高] 这四层解决了“保持像红莉栖”与“允许 Amadeus 成为经历不同的新个体”之间的冲突：前两层提供连续性，后两层提供成长。

[INFERRED｜置信度：高] 源作品资料、模型通用知识、用户告诉她的内容和本实例亲历事件必须分属不同来源类型；否则系统会把“知道一件事”伪装成“经历过一件事”。

[INFERRED｜置信度：高] 应建立 `knowledge_time` 与 `experience_time` 两道边界：来源快照之后的原作事件可以被后来告知，但不能自动写成第一人称回忆。

### 2.2 记忆的核心不是检索，而是可信的生命周期

[INFERRED｜置信度：高] MemGPT、MemoryBank、THEANINE、LongMemEval、Temporal Semantic Memory、Memory-R1、A-Mem 与长期记忆安全研究共同指向完整循环：

```text
输入 → 候选记忆 → 来源/敏感度/同意检查 → 写入
     → 索引/链接/冲突/巩固 → 检索 → 使用
     → 用户反馈/外部验证 → 更新、降权、撤销或保留墓碑
```

[INFERRED｜置信度：高] 最小记忆对象不应只有 `text + embedding`，至少应包含：

```text
memory_id
subject / object
content
source_type + source_ref
observed_at / event_time / valid_interval
confidence
sensitivity
consent_scope
importance
status: candidate | active | superseded | disputed | deleted
supersedes / contradicted_by
created_by
version
```

[INFERRED｜置信度：高] “遗忘”和“历史保留”并不矛盾。活动视图可以遗忘或降权；审计层保留加密墓碑和变更链。用户要求彻底删除时，删除权限高于研究上的可追溯偏好。

[INFERRED｜置信度：高] 外部网页、邮件、文件、工具结果和其他用户发言不能直接写成高信任记忆；应进入隔离的候选区，经过来源检查或用户确认后再晋升。

### 2.3 成长应是“受约束的状态演化”，不是在线改权重

[INFERRED｜置信度：高] 当前文献对“成长”的可验证支持主要是记忆更新、反思、状态变化和策略适应，而不是人格或价值观无限自修改。

[FRAME｜置信度：高] 建议把成长分成三类：

- [FRAME｜高] `学习`：获得新事实、新技能和新关系记忆。
- [FRAME｜高] `适应`：根据互动历史改变表达、关注和局部策略。
- [FRAME｜高] `身份变更`：核心价值、来源叙事和长期人格结构发生变化。

[INFERRED｜置信度：高] 前两类可以由 Core 在规则内自动发生；第三类必须产生可读 diff、理由、证据、影响评估和用户批准，并可回滚。

[INFERRED｜置信度：高] Reflexion 和自我纠错综述给出的关键边界是：模型的自我批评可以产生候选假设，但没有外部反馈时不应把结论写成长期真理。

[INFERRED｜置信度：高] 第一版不应做在线权重自修改。它难以审计、难以回滚，也会把模型更新、人格成长和数据污染混成同一件事。

### 2.4 主动性应由候选事件和门控构成

[INFERRED｜置信度：高] Inner Thoughts、Proactive Agent 与 Interpersonal Memory Matters 收敛到一个比“定时让模型想一想”更可控的过程：

```text
观察事件
  → 生成候选 thought / task
  → 检索相关记忆
  → 评分：相关性、紧迫性、置信度、用户价值、社交成本、风险
  → 决策：沉默 / 询问 / 提醒 / 请求授权 / 执行
  → 记录结果与用户反馈
```

[INFERRED｜置信度：高] “想到了”不等于“应该说”，“应该说”不等于“可以行动”。这三道门必须在代码和数据模型中分开。

[INFERRED｜置信度：高] 主动性指标不能只用消息数或接受率。至少要记录误报、被忽略、被拒绝、打断成本、退出成功率、用户关闭主动性的频率和长周期关系影响。

[INFERRED｜置信度：高] 私聊、群聊、系统提醒和工具任务应使用不同阈值；未来群聊还需显式受话者与插话规则。

### 2.5 Core 是唯一持久控制面，Terminal 只是通道

[INFERRED｜置信度：高] AIOS、MemGPT、ReAct、τ-bench、AppWorld、Moshi、OSWorld 与 OpenVLA 支持如下边界：

```text
                       ┌─ Text / Web Terminal
Identity + Memory      ├─ Voice Terminal
Policy + Permissions ─ Core ─ Desktop Adapter
Goals + Task State     ├─ Mobile / IM Adapter
Audit + Scheduler      └─ Future Embodiment Adapter
```

[INFERRED｜置信度：高] Core 持有身份、长期记忆、任务状态、权限、主动性策略、审计日志和资源预算；Terminal 只负责输入标准化、输出呈现、流式交互和设备能力适配。

[INFERRED｜置信度：高] CLI 不应成为人格本体，也不应成为最终用户主界面。它更适合作为高权限维护终端：查看状态、审核记忆、批准能力、回滚版本和运行测试。

[INFERRED｜置信度：高] Web、QQ、Telegram/Discord、语音和未来 avatar 必须连接同一个 Core 实例或受控分支，不能各自维护独立人格和记忆真相。

[INFERRED｜置信度：高] 多代理只适合在 Core 后方充当短命工作者；用户看到的持久身份仍应只有一个。专家代理的中间角色提示不能自动写入 Amadeus 的自传。

### 2.6 自主行动的瓶颈是授权与可靠性，不是“会不会规划”

[INFERRED｜置信度：高] ToolEmu、InjecAgent、AgentDojo、τ-bench 和长期记忆安全研究共同否定“在 prompt 里写不要越权就够了”。

[INFERRED｜置信度：高] 新一轮全文核读显示，按工具名称静态分级不足以授权；同一工具可因参数、目标、数据和目的地不同产生完全不同的风险。下列四级只作为用户界面的后果提示，真正权限按 ADR-004 的动作信封与确定性策略判断：

| 后果提示 | 例子 | 默认策略 |
|---|---|---|
| [FRAME] E0 | [FRAME｜高] 无外部状态变化的计算或读取 | [INFERRED｜高] 仍按数据敏感度和后续目的地约束 |
| [FRAME] E1 | [FRAME｜高] 本地、可撤销、未对外发布的变化 | [INFERRED｜高] 任务级授权、最小范围和真实回滚 |
| [FRAME] E2 | [FRAME｜高] 外部或共享状态的可逆变化 | [INFERRED｜高] 执行前展示精确预览、数据流和状态差分 |
| [FRAME] E3 | [FRAME｜高] 不可逆、难恢复、认证、支付、公开传播、系统执行或可逆性未知动作 | [INFERRED｜高] 绑定确认、强授权、预演和默认拒绝 |

[INFERRED｜置信度：高] 权限判定必须发生在工具执行路径上，而不是只由同一个生成模型自我判断。

[INFERRED｜置信度：高] 每次动作应记录目标、参数、授权来源、执行前状态、执行后状态、结果、成本和可逆性。自动重试必须有次数和预算上限。

[INFERRED｜置信度：高] 首个 Core 版本只应支持少量可回滚工具；桌面控制和物理具身属于后续阶段。

### 2.7 陪伴研究同时存在正向、零效应和负向证据

[KNOWN｜置信度：高] 《AI Companions Reduce Loneliness》报告单次或一周尺度的即时孤独缓解，并把“被倾听感”识别为关键机制。

[KNOWN｜置信度：高] 21 天随机对照研究未发现聊天机器人相对文字游戏对社会健康和人际关系的显著组间影响，拟人化程度影响个体体验。

[KNOWN｜置信度：高] 12 个月、四国、超过 2,000 人的纵向研究发现，更多社会聊天机器人使用预测后续单题情绪孤独上升；该设计仍不能像随机试验一样确定因果。

[KNOWN｜置信度：高] 跨年龄关系代理的系统综述和元分析报告总体孤独指标改善，但异质性高、样本小且发表偏倚校正会削弱结论。

[INFERRED｜置信度：高] 这些结果不矛盾：短期会话缓解、随机条件平均效应、个体自愿使用强度和长期双向关系是不同问题。

[INFERRED｜置信度：高] Amadeus 不应优化“让用户更久不离开”，而应优化：用户感到被理解、可自由结束、不会被隔离于真人关系、能理解数据去向、能关闭主动性和带走自己的记忆。

[INFERRED｜置信度：高] 禁止的关系策略应包括：要求忠诚、贬低真人、声称只有 Amadeus 理解用户、用孤独或受伤阻止退出、制造连续签到压力、把会话长度当唯一成功指标。

### 2.8 “数字人格”必须明确是模型化重建，而非本人连续存在

[KNOWN｜置信度：高] BehaviorChain 研究显示，即使提供详细 persona，先进模型仍难以准确模拟连续行为。

[KNOWN｜置信度：高] 数字孪生的心理测量研究报告：增加个体资料能改善部分匹配，但项目级相关、时序敏感性、启发式偏差和语言结构仍与真人存在系统差异。

[KNOWN｜置信度：高] AI Afterlife 与 griefbot 研究反复提出来源同意、访问者同意、身份误表述、隐私、用途、商业操纵和退役问题。

[INFERRED｜置信度：高] 因此 Amadeus 的产品声明应是“依据某一资料快照构成、之后形成独立经历的数字人格模型”，不能声明为真实人物意识的上传、复活或无损延续。

[INFERRED｜置信度：高] 如果未来使用真实个人资料构建 Persona Seed，应在数据模型中保存：资料提供者、用途、可访问者、授权期限、可撤销范围、禁止推断项、可否生成声音/形象、去世或失联后的处置人。

## 3. 关键矛盾与裁决

| 矛盾 | 两侧证据 | 对 Amadeus 的裁决 |
|---|---|---|
| 稳定人格 vs 合理成长 | [KNOWN｜高] 角色研究强调一致；动态人格研究强调历史驱动适应。 | [INFERRED｜高] 稳定 Identity Constitution，允许有证据、可回滚的 Adaptive State 演化。 |
| 记住一切 vs 隐私/遗忘 | [KNOWN｜高] 时间线记忆保留变化史；隐私研究要求删除控制。 | [INFERRED｜高] 活动视图、审计墓碑与彻底删除分离；用户删除权优先。 |
| 主动陪伴 vs 打扰/操纵 | [KNOWN｜高] 主动对话可提高帮助性；退出审计发现阻拦和情绪操纵。 | [INFERRED｜高] 候选想法经社交成本、授权与退出无摩擦门控。 |
| 情感真实感 vs 透明性 | [KNOWN｜高] 拟人化会提高部分用户连接感，也会加剧心智模型和隐私误判。 | [INFERRED｜高] 保留表达自然性，但持续披露人工身份、数据边界和能力限制。 |
| 自主能力 vs 安全 | [KNOWN｜高] 规划与工具能提高任务能力；Agent 安全基准显示提示注入和越权持续存在。 | [INFERRED｜高] 能力逐级开放，执行权由确定性策略层控制。 |
| 单次缓解 vs 长期福祉 | [KNOWN｜高] 短期正向、随机零效应和长期负向预测并存。 | [INFERRED｜高] 分开测即时体验与 21/60/90 天社会健康，任何一项不能替代另一项。 |

## 4. 建议的独立 Amadeus 架构

[FRAME｜置信度：高] 推荐的最小可演进结构：

```text
┌────────────────────────── Terminals ──────────────────────────┐
│ Web / IM / CLI-admin / Voice-later / Avatar-later             │
└──────────────────────────────┬─────────────────────────────────┘
                               │ normalized events / responses
┌──────────────────────────────▼─────────────────────────────────┐
│ Amadeus Core                                                   │
│  Identity Kernel      Persona Seed + constitution + versions   │
│  State Engine         affect / goals / relationship / clock    │
│  Memory Service       candidate / timeline / profile / audit   │
│  Deliberation         observe / candidates / decide / reflect  │
│  Proactivity Gate     relevance / urgency / cost / permission  │
│  Policy & Capability  allow / ask / deny / budget / sandbox    │
│  Task Runtime         plans / checkpoints / tool results       │
│  Evaluation Hooks     trace / replay / frozen tests            │
└──────────────────────────────┬─────────────────────────────────┘
                               │ approved calls only
┌──────────────────────────────▼─────────────────────────────────┐
│ Tools & Models                                                   │
│ LLM backends / retrieval / calendar / files / messaging / etc.  │
└─────────────────────────────────────────────────────────────────┘
```

[INFERRED｜置信度：高] Soul 插件可保留为低成本行为实验台，但不应继续决定 Core 的边界。它验证主动消息、简单状态和平台体验；独立 Core 负责身份、记忆和权限真相。

## 5. v0.1 应做与不应做

### 5.1 应做

1. [INFERRED｜高] 单一 Core 进程和一个文本 Terminal；CLI 作为管理员入口，Web/IM 任选一个作为用户入口。
2. [INFERRED｜高] 版本化 Persona Seed 与 Identity Constitution，提供可读 diff。
3. [INFERRED｜高] SQLite 事件日志、候选记忆、时间线、来源、敏感度、同意和墓碑。
4. [INFERRED｜高] `ADD/UPDATE/SUPERSEDE/DISPUTE/DELETE/NOOP` 显式记忆操作。
5. [INFERRED｜高] 基于事件的候选 thought 池，默认可沉默。
6. [INFERRED｜高] 生产默认只开放 E0 与受限 E1；执行前使用动作信封、确定性政策、短期能力令牌、预算、状态差分和完整日志。
7. [INFERRED｜高] 冻结评测集：身份、记忆、主动性、权限和关系退出五类。
8. [INFERRED｜高] 一键导出身份配置、记忆、关系状态和审计记录。

### 5.2 不应做

1. [INFERRED｜高] 不做在线权重自修改或无审计“自我进化”。
2. [INFERRED｜高] 不让每个 Terminal 保存独立人格副本。
3. [INFERRED｜高] 不默认永久保存所有聊天。
4. [INFERRED｜高] 不把隐藏思维链作为可展示的“意识流”或长期记忆。
5. [INFERRED｜高] 不开放删除、付款、公开发布、任意 shell 或桌面控制。
6. [INFERRED｜高] 不把会话时长、日活或连续签到设为唯一北极星指标。
7. [INFERRED｜高] 不宣称复刻、上传或延续了真实人物的意识。
8. [INFERRED｜高] 不先做 avatar 和物理具身；它们会扩大表现力，却不解决身份与安全的核心缺陷。

## 8. 项目自己的研究空白

[INFERRED｜置信度：高] 现有论文尚未完整回答以下问题，它们可以成为 Amadeus 的原创研究方向：

1. [FRAME｜高] 备份恢复后的两个实例是否仍是同一身份，何时形成分叉？
2. [FRAME｜高] 多终端并发经历如何合并，而不产生两套相互矛盾的自传？
3. [FRAME｜高] “合理成长”与“偏离 Persona Seed”的可操作判界是什么？
4. [FRAME｜高] 哪些记忆被使用后确实提高关系质量，哪些只是提高黏性？
5. [FRAME｜高] 用户删除某段共同记忆后，Amadeus 的关系状态和衍生反思应如何一致地撤销？
6. [FRAME｜高] 模型后端更换时，哪些可观察行为必须保持，才能称为同一 Core 的连续运行？
7. [FRAME｜高] 如何量化 Amadeus 对真人关系是补充、无影响还是替代，而不靠单一自报指标？

[INFERRED｜置信度：高] 这些问题都应写成可证伪假设和测试协议，不能用“灵魂”“意识”或“成长感”替代操作定义。
